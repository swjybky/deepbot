# 操作提示 Feedback

> 何时读：任何操作结果、成功、普通信息、警告、错误和顶部浮层提示。
> 代码：[`FeedbackHost.tsx`](../../apps/desktop/ui/components/FeedbackHost.tsx)、[`state/feedback.ts`](../../apps/desktop/ui/state/feedback.ts)

## 全软件统一规则

- 需要显示的操作反馈都走 `notify(level, message)`。禁止在功能卡片、按钮、输入框或编辑器下方挤一行小字，也禁止增加占位框展示结果。
- 顶部居中、脱离布局的紧凑浮层，不撑高卡片、不移动内容、不加遮罩、不抢输入焦点，不要求用户点击“确定”。正文使用 `text-body`（14），禁止降为 caption。
- 最大宽度 480，左右至少 16，顶部 64，避开窗口标题栏；圆角 `rounded-card`，阴影 `shadow-popover`。长文字换行，不截断错误原因。
- 颜色必须来自语义 token，文字同时写明等级，不能只靠颜色区分。提示颜色仅用于操作反馈，不改变 Bot 强调色。
- 同时最多显示三个提示，悬停时暂停计时；关闭按钮、向右滑动和 Esc 可关闭。无提示时不拦截 Esc。
- 主窗口挂载一个 `FeedbackHost`；打开 `Modal` 时，由共用 `Modal` 在其原生根内挂载，主窗口的提示挂载点隐藏，保证浮层在当前弹窗之上。业务页面不自行造浮层或二次打开 Modal。
- `Modal` 创建时用 `untracked` 保留一次内容子树，内容内部仍由自己的响应式绑定更新；不能因为提示队列/生命周期变化重新求值整个 `props.children`，否则会重建表单并丢失草稿。

## 何时不显示提示

- 容易理解的操作不额外加提示小字。控件名称、布局、拖动预览或落点高亮已表达含义时，不再用文字重复解释，也不改成顶部通知。
- 例如 Bot 拖动仅显示头像预览和目标高亮；拖动中及空置顶区都不显示操作说明小字。
- 静态说明仅用于用户缺少信息就无法正确操作的情形；必要的错误原因、风险说明和无障碍标签仍保留。

先判断信息的用途：

| 信息 | 放在哪里 |
| --- | --- |
| 拖动、回车/失焦生效等容易理解的操作说明 | 省略，不改为通知或 tooltip 重复解释 |
| 连接、保存、打开文件等需要告知的操作结果 | `notify()` 顶部浮层 |
| 模型 ID、已配置密钥、事项阶段等常驻数据 | 对应列表行、徽标或卡片 |
| 缺少就无法正确操作的字段含义或风险 | 必要的标签/说明；确认决定使用 [AlertDialog](dialog.md) |
| 无文字图标的动作和对象 | 保留 `label`，用于读屏和悬停提示 |

## 提示等级

| 等级 | 颜色 token / 浅底 token | 适用场景 | 关闭 |
| --- | --- | --- | --- |
| `success` 成功 | `feedback-success` 绿 / `feedback-success-bg` | 连接测试成功、模型拉取成功 | 4 秒自动消失，也可关闭 |
| `info` 信息 | `feedback-info` 蓝 / `feedback-info-bg` | 不阻碍操作的普通通知 | 5 秒自动消失，也可关闭 |
| `warning` 警告 | `feedback-warning` 橙 / `feedback-warning-bg` | 有风险或需要注意，但可继续操作 | 6 秒自动消失，也可关闭 |
| `error` 错误 | `feedback-error` 红 / `feedback-error-bg` | 保存、连接、请求、打开文件或链接失败 | 8 秒自动消失，也可关闭 |

## 使用

```tsx
import { notify } from "../../../state/feedback";

notify("success", "连接成功，模型已返回响应");
notify("info", "配置已同步");
notify("warning", "继续操作会覆盖当前草稿");
notify("error", "连接失败，请检查服务地址");
```

sidecar 的 `model.result`、`error`、连接失败和对话错误在 `state/runtime.ts` 统一转为通知，业务组件只处理数据和 loading，不重复显示通知。每条提示独立计时，同一 ID 的新提示替换旧提示并重新获得完整时长。

模型 ID、已配置密钥、任务阶段等常驻业务状态，以及字段名称和静态使用说明继续使用相应组件。审批、破坏性确认继续使用 [确认机制](dialog.md)，不能用短暂通知代替用户决定。

## 验收

- 模型列表测试连接、编辑器拉取/测试、保存失败均只出现顶部提示，卡片内没有结果行。
- 四级文字颜色各异，正文 14。四级提示按表中的时长自动关闭，悬停暂停，错误比警告多保留 2 秒。连续提示各按自己的时长关闭，同一 ID 被替换后按新提示计时。
- 设置弹窗内能看到并关闭提示，关闭提示不关闭设置；无提示时 Esc 正常关闭设置。
- 主窗口的错误使用同一机制，消息输入不被锁住；已有确认和审批流程继续工作。
