# 窗口与布局

> 何时读：改动窗口结构、加新的面板 / 页面、处理标题栏和窗口拖动、改对话区。
> 代码：[`AppShell.tsx`](../apps/desktop/ui/AppShell.tsx)、[`App.tsx`](../apps/desktop/App.tsx)、`ui/features/*`。

## 窗口

- 默认 1280×800（设计稿画板尺寸），`App.tsx` 启动时 `Window.setFrame` 设置。
- 系统标题栏隐藏（`Window.setTitleBar({ style: "hidden", height: 64 })`），应用画满整个窗口；
  **系统自己的窗口按钮保留**（macOS 红绿灯、Windows 标题按钮、GTK 按钮）。不要自己画最小化 / 最大化 / 关闭按钮——设计稿右上角那三个只是示意。
- 任何贴近窗口顶边的元素都要用 `titleBar()`（`nsh/desktop`）让开系统按钮：`titleBar().right` 是右侧按钮占的宽度，`titleBar().left` 是左侧（macOS）。
  例：分享按钮在面板关闭时 `right = titleBar().right + 16`。
- 可拖动窗口的区域加 `desktop={{ windowDrag: true }}`：侧栏顶部按钮行、对话区顶部 64pt 条、信息面板顶部。里面的按钮照常可点。

## 三栏

```
┌──────────┬──────────────────────────────┬──────────┐
│ Sidebar  │ ChatPane                     │ BotInfo  │
│ 可拖动   │ flex-1（min-w-0）             │ 可拖动   │
│ sidebar  │ background                   │ card     │
└──────────┴──────────────────────────────┴──────────┘
              Modal（设置 920×660 / 创建 440）盖在整个窗口上
```

| 区域 | 宽 | 背景 | 分隔 | 文件 |
|---|---|---|---|---|
| 左侧栏 | 默认 280，最小 180，可拖动 | `bg-sidebar` | 共用拖动分隔线 | `features/sidebar/Sidebar.tsx` |
| 对话区 | 剩余，最小 320 | `bg-background` | — | `features/chat/ChatPane.tsx` |
| Bot 信息面板 | 默认 320，最小 240，可拖动；关闭为 0 | `bg-card` | 打开时显示拖动分隔线 | `features/bot-info/BotInfoPanel.tsx` |

- 信息面板通过 `setInfoPanel(open)`（`state/ui.ts`）开关。`ResizableColumns` 仅对右侧面板容器使用 280ms 原生 `translateX` 动画；**不要直接 `infoPanelOpen.set()`，不要给开关使用全局 `LayoutAnimation`**。全局布局动画会把聊天正文换行后的高度、上下位置一起插值，引起整段消息上下滑动。
- 右栏展开时从窗口右侧向左滑入，关闭时反向收回；面板始终按完整宽度布局，在根容器边界裁切。聊天区按最终可用宽度一次重排，消息本身不做高度或纵向位移动画。处于底部时保持最新消息靠近输入框，不能把重排事件当成用户主动向上滚动；阅读历史时不强制回到底部。关闭完成后隐藏面板可见性，立即关闭交互，防止屏外内容被命中。连续开关从当前位移反向过渡，拖动宽度即时跟随，系统减少动态效果时直接到位。
- 三栏用共用 `components/ResizableColumns`；各业务栏的根节点使用 `min-w-0 flex-1`，内容随所在栏宽度伸缩，不再写固定宽度或重复画边框。
- 分隔线保持 1pt（`bg-border`），悬停或拖动时用 `bg-ring`；透明命中带宽 9pt，使用 `col-resize` 光标。原生 responder 捕获整次拖动，即使鼠标离开细线也继续跟随，松开后结束；无障碍支持增减栏宽。
- 两侧宽度保存在组件 signal 中，中央占用剩余空间；拖动不触发布局动画。关闭再打开右栏保留本次调整，窗口缩小时临时压缩侧栏，为对话留出最小宽度，放大后恢复期望宽度；窗口窄于三栏最小宽度之和时，按比例降低最小值，避免水平溢出。
- 带遮罩的全窗口覆盖层一律用 [Modal](components/dialog.md)，不要在 AppShell 里绝对定位一层。操作反馈统一用 [Feedback](components/feedback.md) 的非阻塞顶部浮层。
- Bot 信息面板只保留「动态 / 资料库 / 配置」三个一级 Tab。事项详情、资料和记忆预览、规矩及例行管理都使用 [全窗口弹窗](components/dialog.md)。关闭弹窗回到原 Tab，保留列表滚动及折叠状态。面板顶部关闭按钮单独收起右栏。切换 Bot 时回到该 Bot 的动态，基础 Bot 字段继续在「配置」就地编辑。

## 左侧栏

自上而下：操作行（搜索、创建新 Bot，`IconButton` outline，右对齐，`px-4 pt-4 pb-2 gap-2`）→ 置顶 Bot 磁贴（96×92，头像 64 + 星标）→
Bot 列表（`Scroll`，行见 [list.md](components/list.md#侧栏-bot-行)）→ 账户行（无顶部分隔线，左边头像 + 名字打开设置，右边"应用与插件"）。

## 对话区

- 顶部使用 `components/FloatingHeader`：64pt 透明绝对定位浮层，居中 **Bot 胶囊**（h-10，头像 30 + 名字，`shadow-float`，点击开关信息面板）；不占消息区高度、不铺整条背景，滚动消息从胶囊下方经过。浮层空白使用 `pointerEvents: "box-none"`，保留内容交互；子控件保留点击，胶囊可拖动窗口。消息 Scroll 从对话区顶边铺开，内容顶内边距 76pt，仅在起始位置为首条消息让位。
- 消息列：`w-full min-w-0 max-w-[960px] self-center`，与输入条共用聊天区中线。宽窗多出的空间均分在消息列两侧，窄窗保留外层 `px-6`。用户消息贴列右边，Bot 回复和提问卡片贴列左边。列内使用 `gap-2.5`，消息区 `selectable`（可以跨气泡选择复制）。
- 底部输入条：`max-w-[760px]` 居中，见 [input.md](components/input.md#消息输入条)。

### 回复等待动画

- 使用 `components/ThinkingIndicator`，放在消息列末尾，靠左、无气泡底色。由当前会话的前台运行状态控制挂载。
- 三颗 `size-2` 的圆点通过 `color` 属性使用当前 Bot 的头像颜色，切换 Bot 或修改头像颜色时同步更新；以 1200ms 周期缩放、淡入淡出，依次错开 160ms。右侧用 `text-body text-faint-foreground` 显示短中文动作，文案更新时保持圆点动画。
- 使用 NSH 原生 motion，不用 JS 定时器；卸载时停止动画。系统减少动态效果时保持圆点大小不变，只保留轻微明暗呼吸，避免等待状态看起来卡住；不修改系统设置。回复等待不禁用输入条。

### 消息气泡（`features/chat/MessageBubble.tsx`）

| | 用户 | Bot |
|---|---|---|
| 对齐 | 右 | 左 |
| 底色 / 文字 | `botFill(accentColor())` / `text-primary-foreground` | `bg-muted` / `text-foreground` |
| 消息行宽度 | 最多占消息列的 100% | 最多占消息列的 85% |
| 共同 | 气泡 `max-w-[640px]`，含左右内边距，正文约容纳 40 个全角字。窄栏在扣除操作按钮占位后收缩换行，短消息按内容收缩 | |
| 样式 | `min-w-0 shrink rounded-[18px] px-[15px] py-2.5 text-message font-medium`（双方正文都用 500 字重，便于看清） | |

Bot 的文字回复用 `components/MarkdownText`（NSH `TextView`）渲染 Markdown：加粗、列表、标题、引用、代码、表格、链接。纯文字回复须与普通气泡一致：正文 `text-message font-medium text-foreground`，加粗 `**…**` 为 `font-semibold`，单个换行保留为换行（围栏代码除外），不套用文档排版的大标题；标题最大 `text-title`，代码块 `rounded-control border-edge bg-card`。正文里的链接点击后用 `openExternal` 打开。用户消息仍按原样显示纯文本，不解析 Markdown。

事项交付和关联到事项的汇报在 Bot 气泡正文上方增加「事项 · 标题」一行。用 `text-caption font-semibold text-muted-foreground`，宽度最多 320px，窄栏随气泡缩小，超出用单行省略。标签来自事项标题，正文仍是复制和引用的内容。

链接不进气泡，显示为链接卡片：330 宽，`rounded-2xl border-edge bg-card`，地球图标 20 + 域名（semibold）+ URL（`text-meta`，单行省略）。
附在消息上的图片放在同一气泡中，文字跟在图片下方。图片预览宽度随气泡收缩，保持原图比例。加载失败在原位置提供重试。新消息类型的组件放在 `features/chat/` 下。

悬停消息行时显示垂直居中的 `ghost` 图标按钮。用户气泡左侧显示「回复」，Bot 气泡右侧依次显示「回复」和三点「更多」。「更多」打开原生菜单，菜单内提供「复制」。气泡与操作区、按钮之间都留 `gap-2`，每个按钮预留 `size-8`，使消息尺寸和对齐在悬停前后保持一致。移到按钮上保持显示，离开消息行后隐藏。图标按钮带无障碍标签和悬停提示。

## 状态放在哪

| 状态 | 位置 |
|---|---|
| Bot 列表、当前 Bot、强调色 | `ui/state/bots.ts` |
| 面板开关、当前弹窗、设置分类、信息 Tab | `ui/state/ui.ts` |
| 用户设置 | `ui/state/preferences.ts` |
| 测试占位数据 | `apps/desktop/FixtureApp.tsx`；生产界面不引用测试数据 |
| 只属于一个组件的临时状态（输入框草稿、创建表单） | 组件内部 `signal()` |

## 后台刷新与交互状态

- 收到快照、流式回复或后台进度的页面，只按稳定业务 ID 和实际开合或模式变化挂载交互区域。NSH 的弹窗用 `computed` 派生开关，条件子树用 `<If>`，列表用稳定 ID 的 `<Each>`。刷新时让现有节点更新文字、状态和可用性。
- 禁止把每次刷新都会换引用的记录、数组或版本号当成 key，或在跟踪这些数据的 JSX 三元表达式里构造整个交互分支。草稿只在本次编辑开始或目标变更时初始化。禁止用延迟触发或关闭动画掩盖节点重挂载和草稿重置。
- 用同一原生宿主、布局和输入位置做刷新前后对照。悬停时分别观察静止、持续刷新、同一命中区内移动和越界进出。用截图序列或录屏检查背景只在真实边界变化时切换，并用 `nsh test --target linux --trace` 核对命中节点是否被移除和重建。编辑场景同时核对键入或粘贴后刷新、保存、取消和切换目标。
- 允许在目标、交互模式或可用分支实际变化时换节点。Headless 用例可以检查草稿和展开状态，悬停画面、系统输入法和 Wayland/X11 分别按实际执行的原生范围记录。

## 右侧配置区宽度注意事项

- 右侧内容区中的配置卡片和表单必须沿横轴撑满可用宽度，不能按文字或输入框的内容宽度收缩，留下大块右侧空白
- 独立编辑器根节点使用 `w-full min-w-0 self-stretch`；两列表单行使用 `w-full min-w-0`，两列用 `flex-1 min-w-0` 平分
- 列表缩进容器用 `self-stretch min-w-0` 扣除 margin/padding 后铺满；带左缩进的容器不要直接加 `w-full`，避免 100% 宽度再叠加 margin 导致右侧溢出
- 编辑器右边缘应与提供方标题的内容右边缘对齐；只保留设计规定的外层 padding 和左侧层级缩进，不用固定像素宽度补救
- 验收覆盖“展开提供方 → 编辑已有模型”和“添加模型”，并比较父级可用宽度与编辑器实际宽度；单独展示编辑器的截图不能代替嵌套列表场景

## 布局与动效验收

| 场景 | 实际检查 |
| --- | --- |
| 放大/缩小窗口、拖动两条分隔线 | 消息列随聊天区伸缩并居中，达到 960px 后两侧留白同步增长。两种气泡在 640px 以内伸缩，窄栏文字换行且无溢出，短消息贴合内容 |
| 顶部胶囊与消息滚动 | 胶囊悬浮在正文上，首条消息让位；透明区域不阻断滚动和消息操作 |
| 用户/Bot 消息分别悬停 | 用户回复图标在左，Bot 的回复和更多图标在右。按钮出现和消失时气泡宽度与对齐保持一致 |
| 长对话在底部时展开/关闭右栏 | 面板横向运动；正文不做纵向扫动，最新消息仍靠近输入条 |
| 阅读历史时开关右栏 | 不强制跳回最新消息；检查快速开关的中间帧和关闭后不可命中 |
| 等待回复、切换 Bot、减少动态效果 | 等待动画与 Bot 同色，状态结束即停止，输入仍可用；减少动态效果时按组件规则降级 |

截图比较使用相同窗口、字体、内容和滚动位置；动效另取连续关键帧或录屏，不能用最终一张图判定。执行和交付要求见 [verify 技能](../skills/verify/SKILL.md)。
