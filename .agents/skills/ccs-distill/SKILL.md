# ccs-distill

[ccs-retro](../ccs-retro/SKILL.md) 从失败里修流程，本技能从成功里沉淀能力。两个入口：提炼本次对话、批量挖掘历史对话。都只给清单和方案，等用户确认后再改。路径都以仓库根目录为起点，改动只写项目目录。

## 什么值得提炼

| 候选 | 处理 |
| --- | --- |
| 用户纠正过 agent 的判断 | 价值最高，优先提炼 |
| agent 的思路被运行结果、截图或用户确认验证有效 | 提炼，附证据 |
| 本次用到、以前也出现过的做法 | 提炼，写明出现过的对话或提交 |
| agent 提出但没验证的建议、只适用于本次任务的做法 | 列出并标「不提炼」，写明理由 |

## 提炼本次对话

1. 回顾本次对话，按上表把候选分类。用户指定了重点时，先处理重点。
2. 每个候选写清四项：什么情况下、做了什么、为什么有效、证据（命令输出、截图、报告链接或用户原话）。没有证据的降为「不提炼」。
3. 先查已有内容：`.agents/skills/`、`skills/verify/`、`references/features/`、`rules/README.md`。已被覆盖的标「已有」，指出位置。
4. 给每个要提炼的候选选落点，按 ccs-mode「[错误变规则](../ccs-mode/SKILL.md#错误变规则)」从上往下选第一个能用的：能写进类型或接口、能做成检查、能补回归测试、能交给 verify CLI 的，都不写成文字。只能靠人判断的再选：
   - 某个功能特有的坑或用户路径 → 功能地图对应页的「注意事项」
   - 某类任务的步骤 → 补进已有剧本的某一步
   - 已有四个剧本都放不下，且至少出现过两次 → 新建剧本
   - 都不合适 → 不沉淀，说明理由

完成标准：输出提炼清单（分类、四项说明、落点、拟改的文字或命令形式）后停下，等用户确认。

## 批量挖掘历史对话

1. 先告诉用户打算读哪些记录、时间范围，等确认后再读。可用来源：
   - Claude Code：`~/.claude/projects/-home-swj-project-deepbot/*.jsonl`
   - Codex：`~/.codex/sessions/<年>/<月>/<日>/*.jsonl`，只取首行 `session_meta.payload.cwd` 为本仓库的
   - 项目内：`git log`、[CHANGELOG.md](../CHANGELOG.md)、`notes/handoff/`
2. 只读，不改历史记录和全局配置。用脚本抽出用户消息和最终回复，不整份读入上下文。
3. 找跨对话反复出现的三类内容：同一种做法、用户的同一种纠正、反复踩的坑。坑交给 ccs-retro 处理，本技能只记下转交。
4. 每条写明出现在哪几次对话（会话 id 和日期），再按「提炼本次对话」第 2 到 4 步处理。

完成标准：同上，输出清单后停下等确认。

## 确认后修改

- 补剧本：只改对应那一步，写成动作加可观察的完成标准，守住 ccs-mode「[改进剧本](../ccs-mode/SKILL.md#改进剧本)」须保留的步骤。改完仍在一页以内，超了就删掉已被工具或规则接管的内容，不能删就合并步骤。
- 新建剧本：放在 `.agents/skills/playbooks/`，在 ccs-mode 第 3 步分派表和「须保留的步骤」表各加一行，给三个示例任务说明分派结果。
- 工具、检查、功能地图：按 ccs-retro「修复」一节对应条目的要求做。
- 列出改动前后的差异。

每次修改都要：

1. 在 [CHANGELOG.md](../CHANGELOG.md) 记一行，写日期、沉淀了什么、来自哪次合作。
2. 运行 `pnpm --silent verify check`，全部通过。
3. 提醒用户开全新对话回归，提示词如下。

> 这是一次流程回归测试。请只根据项目里的技能、剧本和功能地图，完成这个任务：<能用上新做法的小任务>。完成后报告：1. 是否自然用上了这个做法：<描述>；2. 过程中还有哪些说不清、走不通的地方。

## 防膨胀

本技能天然倾向加内容。每提炼一条，同时看落点所在文档有没有能删或合并的旧内容。剧本数量可以慢慢增长，单个剧本的长度要保持稳定或变短。定期体检时先用 ccs-retro 找问题，再用本技能找亮点。
