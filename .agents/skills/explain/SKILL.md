# 讲解代码和设计

先读当前工作树里相关的实现和调用方，再用 `git log -- <文件>`、`git show <提交>` 或 `git blame` 查实际变更。查阅相关代码注释和能找到的讨论。证据附文件路径和行号、提交号或讨论链接。

## 怎么运行

从用户操作或代码入口讲起，顺着真实调用、数据变化和结果讲一遍。指出涉及哪些文件和函数，术语用大白话解释。

## 为什么这么写

根据提交记录、注释或相关讨论说明当时解决的问题和取舍。推断要写明依据。找不到设计理由时，说明查过哪些材料和哪一点仍找不到依据。
