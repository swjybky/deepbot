# 远端 T3 私网 HTTP 派活验证

## 复现

在 Linux GTK/X11 私有显示中运行正式桌面入口。通过「设置 → 连接 → 添加执行器」填写隔离地址 `http://10.77.0.2:23118/mcp`、测试派活凭据及完全访问权限，审批留空。修复前，单击添加依然出现「T3 Code 审批连接需要本机回环地址或 HTTPS」，表单未收起。verify 实例 `bcb8e9e28c31ae83` 保留了保存后的截图和失败日志。

远端地址解析复用了审批传输校验，且通用 MCP 客户端会拒绝非回环 HTTP。修复后由远端 T3 派活单独准入局域网私有 IP。配对和 MCP 请求保持原认证并拒绝重定向。编辑地址、读取项目、派活和结束已建立的会话均使用对应实例的身份检查。审批凭据仍走独立的传输校验。

## 最终源码验证

隔离网络用 veth 连接两个无外网路由的网络命名空间，DeepBot 侧和 T3 侧分别使用 `10.77.0.1` 和 `10.77.0.2`。

最终源码指纹为 `40ae3011411791c297b11f010744903414ee9449c42a7e66d4293d80d45f4fe1`。在同一 verify 实例复验连接卡片、回环远端 T3 和每 Bot 并发，原生四组场景均通过。逐张复核 23 张截图。

- 原生场景 `remote-t3-lan` 先显示 HTTP 明文说明，填入审批凭据时显示审批传输错误，清空后保存可用卡片。在事项详情选中远端项目并改派，收到了隔离 T3 替身的执行结果。该场景使用 verify 实例 `7bea5bfc085e1ec6`。
- 用官方 T3 Code `0.1.12-nightly.20261124.5178` 监听 `http://10.77.0.2:3773`，使用临时配对链接完成 OAuth 和 MCP 握手。保存后的配置文件权限为 `0600`，公开状态仅显示审批是否可用。DeepBot 发现官方项目并派出实际 T3 线程，线程返回 `T3_VERIFY_COMPLETED`，事项进入验收。DeepBot 停止并重新打开同一隔离数据目录，再次查到项目、同一执行器和原线程。官方 T3 的模型请求由本地确定性替身响应。
- 用隔离测试证书建立 HTTPS 连接后，再次使用官方 T3 完成配对和派活。单独填写设备凭据，核对 WSS 审批通道返回的是同一线程的投影。
- 回归覆盖 RFC 1918、IPv6 ULA、HTTPS、回环地址、拒绝公网 HTTP 和普通 MCP 私网 HTTP、禁止携带查询凭据、配对链接来源不一致和环境 ID 不匹配。审批在私网 HTTP 上有独立且早于凭据交换的校验。
